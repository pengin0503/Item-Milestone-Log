### P15. 持ち運べる収納の中身も数える（opt-in）

**目的と根拠**
- Mod パックでは素材をバックパックやシュルカーボックスに入れて持ち歩くことが多く、数量ターゲット（例: ダイヤ ×1000）は「インベントリに同時に持つ」では達成しにくい

**仕様案**
- Config `countContainerContents`（boolean、既定 false）。true のとき、所持数にインベントリ内の収納アイテムの中身を加える: バニラのコンテナ（シュルカーボックスの内容）、バンドルの内容、NeoForge のアイテムのハンドラ（バックパックなど）。入れ子は1段まで
- 判定・進捗（Q9 / F1）・記録の確定のすべてに適用する

**コスト・リスク**: 中〜大。
- **1.0.1 の決定を覆す**（`QUANTITY_SPEC_1.0.1.md` Q2 と FEATURE_SPEC_1.0.1 F14 で「シュルカーボックスの中身・他 Mod のストレージは数えない」と決めている）
- スキャンのたびに収納の中身を読むため、負荷が増える（大きなバックパックを多く持つ場合）
- バックパックによっては中身をワールド側に持ち、ハンドラの取得でデータを読み込むものがある（Mod ごとの挙動の確認が要る）

**推奨度**: 要判断（採用するなら 1.1.0 ではなく、実際の Mod パックでの検証を前提に後の版を勧める）

**目的と根拠**
- 世界初やプリセット制覇はチャットの1行で流れてしまい、特別さが伝わりにくい

**コスト・リスク**: 小。ただし世界初については F7（`title %player% ...`）でも実現できるので重複がある。

**推奨度**: 低

### P44. Discord の送信テスト（`discordtest`）

**目的と根拠**
- Webhook の設定が正しいかを確かめるには、実際に何かを記録するしかない。1.1.0 では F35（404・401 で送信を止める）、F39（`env:`）、F4・F18（Embed・言語）と、設定の組み合わせが増える。失敗はサーバーログの warn にしか出ず、管理者が気づきにくい

**仕様案**
- `/milestonelog discordtest`（権限レベル2。1.2.0 の F43 ではノード `itemmilestonelog.discordtest` を足す）。F24 の `renameitem` と同じ理由でルート直下に置く（`admin <player>` の下だと、その名前のプレイヤーと衝突する）
- 固定のテスト文面（lang キー `discord.itemmilestonelog.test`、F18 の `discordLanguage`。F4 の Embed の設定に従う）を、通常と同じキューで送り、結果を実行者に返す
  - 結果はサーバースレッドに戻してから返す（送信は別スレッド）。返す内容: 送れた（HTTP の状態コード）、HTTP 404 / 401（「Webhook が削除されたか URL が誤っている」）、429、通信の失敗（例外のクラス名だけ）、URL が未設定、F39 の環境変数が無い（変数名だけ）。**URL は出さない**（既存の方針）
  - F35 で送信を止めている URL にも送る（直した後の確認のため）。成功したら F35 の停止を解く
  - 同時に1件だけ（送っている間は「送信中」と返す）。実行者がその間にログアウトしたら、結果は捨てる
  - 1.2.0 の F46 があれば `discordtest worldfirst` で世界初用の Webhook を試す
- Config は追加しない（管理者のコマンド）

**コスト・リスク**: 小。送信の経路は既存のものを使う。

**推奨度**: 推奨（1.1.0 の Discord の機能の確認手段になる）

### P45. クリエイティブで記録が止まっていることを本人に伝える

**目的と根拠**
- クリエイティブ・スペクテイターから戻るとき、持っていたアイテムに「クリエイティブから持ち出した」印が付き（`Tracker.onGameModeChange`）、そのアイテムがインベントリから一度無くなるまで記録されない（スキャンは印のあるアイテムを数えず、印は持たなくなったときか、所持数 0 から拾ったときに外れる）。この規則は乱用を防ぐための 1.0.1 の決定だが、本人には何も知らされない
- `targets` は印のあるアイテムの所持数を 0 と表示する（`MilestoneCommands.targets` の `carried.contains(...) ? 0 : ...`）。持っているのに 0 と出て、記録されない理由が分からない。不具合の報告につながりやすい
- lang ファイルにクリエイティブに関する文面は1つも無い

**仕様案**
- 印が付いたとき、その中に未記録のターゲットのアイテムがあれば、本人に1行（件数 = 種類の数）: en "%s target item(s) you carried out of creative mode will not be recorded until they leave your inventory." / ja 「クリエイティブから持ち出した目標のアイテム（%s 種類）は、一度インベントリから無くなるまで記録されません。」
- `targets` の、印のあるアイテムの未記録の行の末尾に「（クリエイティブから持ち出し中）」を付ける（所持数の 0 の理由が分かるように）
- `/milestonelog`（概要）で、記録の一時停止中（`ignoreCreativeAndSpectator` が true でクリエイティブ・スペクテイター）なら1行: 「クリエイティブ・スペクテイターの間は記録されません。」
- GUI は変えない（印は同期データに無い。1.2.0 の F25 の追加ペイロードで送れば、状態の行の文字を変えられるが、この候補には含めない）
- 1.2.0（F8b）: タグのターゲットに含まれるアイテムも対象
- Config は追加しない（既存の挙動の説明を出すだけ）

**コスト・リスク**: 小。記録の規則は変えない。

**推奨度**: 推奨

### P46. アイテム1つの状態を見る（`info <item>`）

**目的と根拠**
- あるアイテムについて「自分の目標か・記録済みか・世界初は誰か・何人が記録したか」を知るには、`targets`、`firsts`、F13 の `top <item>` を別々に見る必要がある。1.2.0 の F42 のツールチップは Mod 入りのクライアントでしか出ない

**仕様案**
- `/milestonelog info <item> [<count>]` と `info hand`（OP 不要。実行者はプレイヤー）。`<item>` は `reset` と同じ `IdentifierArgument`
- 出力: 自分の状態（目標でない / 目標・所持数 / 記録済み・記録の整形）、そのキーの世界初の保持者と記録（F47 の名前の規則）、記録したプレイヤーの数と自分の順位（F13 の `top <item>` と同じ数え方。`allowLookup` が false で `isPrivileged` を満たさない者には、人数と順位を出さない。F14 で隠している人は数えない）
- 1.2.0（F8b）: そのアイテムを含むタグのターゲットの行も出す

**コスト・リスク**: 小。集計は F13 の関数を使う。

**推奨度**: 検討（バニラクライアントの人にとっての F42 の代わりになる）

### P47. 留守の間の世界初をログイン時に知らせる

**目的と根拠**
- 世界初のアナウンスはオンラインの人にしか届かない。F37 で保存する `lastSeen`（最後にいた時刻）を使えば、留守の間に起きた世界初を、戻ったときに知らせられる

**仕様案**
- Config `loginWorldFirstSummary`（boolean、既定 false）
- ログイン時、`lastSeen` を新しい時刻で書き換える**前の値**が 0 でなければ、世界初のうち epochMillis が (前の `lastSeen`, 現在] にあり、本人以外が保持者のものを、新しい順に最大5件と「ほか N 件」で1通にして送る（0件なら送らない）。名前は F47 の規則
- `muteBroadcasts` の人には送らない（他人の記録のお知らせを止めている人）
- サーバーが落ちてログアウトが書かれなかった場合は、前回のログイン以降が対象になる（害は無い）

**コスト・リスク**: 小。

**推奨度**: 検討

### P48. 通常の記録を、Discord の通知音なしで投稿する

**目的と根拠**
- 記録の多いサーバーでは、投稿のたびにチャンネルの参加者に通知が飛ぶ。Discord の Webhook の実行は `flags` に `SUPPRESS_NOTIFICATIONS`（`1 << 12` = 4096。「プッシュとデスクトップの通知を起こさない」）を受け付ける（Discord の文書の Execute Webhook と Message Flags、2026-11-23 に確認。Webhook で設定できるのは `SUPPRESS_EMBEDS`・`SUPPRESS_NOTIFICATIONS`・`IS_COMPONENTS_V2` だけ）

**仕様案**
- Config `discordSilentRecords`（boolean、既定 false）。true なら、世界初を含まない記録の投稿（F27 のまとめた投稿を含む）に `flags: 4096` を付ける。世界初、F19 の制覇、F9 のダイジェストは従来通り通知する
- 1.2.0 の F46 で世界初を別の Webhook に送っている場合、`discordWebhookUrl` への記録の投稿はすべて通知音なしになる

**コスト・リスク**: 小。投稿の JSON に1項目足すだけ。

**推奨度**: 検討

### P49. プリセットの表示名を言語ごとに書けるようにする

**目的と根拠**
- 組み込みのプリセットの表示名は lang キーで言語ごとに出るが、カスタム（JSON）と 1.2.0 の F21 のデータパックのプリセットの `name` は文字列1つだけ（`Presets.parsePresetFile`）。F21 でプリセットを配る人は、複数の言語の利用者に向けた名前を付けられない
- サーバーは同期をプレイヤーごとに作っている（`MilestoneService.createSyncPayload`）ので、受け取る人の言語の名前を選んで送れる。ペイロードの形式は変わらない

**仕様案**
- `name` に文字列に加えて、オブジェクト `{"en_us": "...", "ja_jp": "..."}` を受け付ける。選ぶ順: 受け取る人の言語 → `en_us` → オブジェクトの最初の値 → ID。文字列の場合は従来通り
- 使う箇所: GUI の同期（受け取る人の言語）、チャット（`preset list`、F5 の制覇、F16 の見出しなど。受け取る人の言語）、F19 の Discord（`discordLanguage`）
- 256 文字の上限は値ごと。G2 の上書き保存は、オブジェクトの `name` もそのまま引き継ぐ
- 1.0.1 / 1.1.0 はオブジェクトの `name` を読めない（文字列でなければ ID を表示名にする既存の動作。読み込み自体は失敗しない）。README に書く

**コスト・リスク**: 小〜中。

**推奨度**: 検討（F21 と同時に入れると効果が大きい）

**コスト・リスク**: (a) 小、(b) 中、(c) 中（新しいコードの置き場所を決めるだけで、既存のコードは移さなくてよい）。

**推奨度**: 要判断（オーナーが issue #20 を閉じているため）

### P51. GameTest で、サーバー側の処理を本物の ServerPlayer で確かめる

### P52. 実装を始める前に、仕様書を版ごとに分ける

**目的と根拠**

- 分けた後は、1.1.0 の文書を 1.1.0 の実装の間の唯一の基準にする

**コスト・リスク**: 小（文書の作業だけ）。分けた後に両方を直す手間が増えるので、候補の追加が続く間は分けない。

### P53. CurseForge / Modrinth への公開を CI から行う

**目的と根拠**
- 1回のリリースで、4バージョン × 2サイト = 8 個のファイルを手で上げ、それぞれに Minecraft のバージョンと NeoForge を指定している。1.1.0 と 1.2.0 で 16 回になる。バージョンの付け間違い（別のバージョンの jar を上げる）は利用者のクラッシュに直結する
- CI は既にタグで GitHub Release を作り、4つの jar を添付している（release ジョブ）

**仕様案**
- 手動で起動するワークフロー（`workflow_dispatch`。タグを指定）で、そのタグの release の jar を、CurseForge と Modrinth の API で上げる。ファイル名の Minecraft のバージョンから、各サイトのゲームバージョンを決める。説明は CHANGELOG のその版の節
- API のトークンは、オーナーがリポジトリの secrets に入れる（Modrinth は個人のアクセストークン、CurseForge は API トークン）。第三者の Action を使う場合はコミットの SHA で固定する（トークンを渡すため）
- `docs/updates.json` の更新は従来通り手で行う（公開を確かめてから）
- 各サイトの API の細部（CurseForge のゲームバージョンの ID の取り方など）は、採用時に確かめる

**コスト・リスク**: 中。公開は取り消しにくい操作なので、起動は手動に限る。

**推奨度**: 低（CurseForge の審査が通り、手作業の負担が実際に問題になってからでよい）
